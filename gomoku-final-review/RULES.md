# 展评赛事规则（平台执行版）

## 参赛与执行

- 参赛者提交公开 GitHub 仓库；仓库名和实现文件名均可任意。名单文件为 UTF-8 `roster.csv`，至少有 `student_id,display_name,github_url`，可选 `submission_path` 指定仓库内的实现文件。
- 平台只接受 `https://github.com/<owner>/<repo>` 形式的公开地址，浅克隆且记录 commit；不执行仓库中的构建脚本、测试或其他代码，只提取 `chooseMove` 的 C++ 实现文件。
- 平台冻结课程 `gomoku.hpp`、`student_api.hpp` 与 `main.cpp` 的 SHA-256 快照。学生代码只能实现 `gomoku::chooseMove`。
- 每回合启动新进程，输入完整局面，标准输出只能是一行 `x,y`。裁判依次检查输出、坐标、占位、课程规则库中的黑方禁手、胜负与和棋。
- Docker 运行时禁网，限制为 1 CPU、512 MiB、64 PID、只读根文件系统；单手硬上限 2.1 秒，累计思考时间 45 秒。

## Opening 与对局

- 使用 Gomocup 2026 Renju 15×15 的 12 个官方五手开局；坐标以 `(7,7)` 为中心，开局后第六手由白方走。
- 每一 pairing 有两局：同一开局和对称变换，双方黑白互换。
- 全部随机决定由公开 Seed、平台固定的 PCG32 算法和冻结 manifest 复现。

## 小组与淘汰

- 21 人随机分为 A 组 6 人、B/C/D 组各 5 人。circle method 排成五轮，总计 45 个 pairing、90 局。
- 每组前二进入八强：`A1-B2`、`C1-D2`、`B1-A2`、`D1-C2`。八强、半决赛使用两个不同开局，决赛使用三个。
- 胜 1 分、和 0.5 分、负 0 分。小组排名依次比较积分、同分小循环、Sonneborn-Berger、胜局数。
- 仍同分时最多追加三轮双局换色加赛；之后依次比较白方成绩、该阶段可信累计思考时间（小者优先）、学号升序。

## 审计与展示

- SQLite 和 JSONL 事件日志保存抽签、开局、每手棋盘、思考时间、程序输出、终局原因和积分。
- 回放从 opening 逐手调用冻结规则库；只读验证，不接受最终棋盘快照替代。
- 大屏可展示 1–4 个棋盘；默认 6 人组显示三盘、5 人组显示两盘，操作台可同时启动任意四局。
